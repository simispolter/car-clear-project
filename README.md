# רכב ברור — פרויקט עצמאי להשוואת רכבים

גרסה ראשונית עובדת בעברית, RTL, עם קטלוג אמיתי מתוך משרד התחבורה. אין תלות ב־Sites, בבונה אתרים או בחשבון דרייב בזמן שהאתר פועל. אפשר לאחסן על שרת Linux או שירות שמריץ Docker/Python ולחבר דומיין בבעלותכם.

## מה כבר עובד

- 101,824 רשומות דגם ושנת ייצור; 138 יצרנים ו־6,018 צירופי יצרן ושם מסחרי. אלה **אינם 101,824 דגמים מסחריים שונים**.
- חיפוש בעברית ובשמות המקור, סינון תקציב לפי מחירון חדש, שנת ייצור, הנעה, מושבים ודלתות.
- מסלול קצר עם שלוש בחירות: תקציב, מספר מושבי בטיחות שצריך לבדוק, סוג הנעה.
- השוואה של עד שלוש גרסאות, שמירת הבחירה בדפדפן, קישור שיתוף, הצגת הבדלים בלבד והדפסה.
- מפרט, מקורות, שדות מקוריים, מצב הכיסוי ושלושה מדריכים.
- מחשבון הוצאות דלק לפי ההנחות שהמשתמש מזין; ההערכות אינן נכתבות למאגר.
- HTML שנוצר בשרת, כתובות קבועות, canonical, JSON-LD, sitemap מפוצל, noindex לסינונים ולדפים ללא תוכן ערוך.
- SQLite עם אינדקסים, API מדופדף, בדיקת קלט, שאילתות פרמטריות, אבטחת כותרות, בדיקות אוטומטיות ו־Docker.

## מגבלות שאסור להסתיר

1. מחירון חדש לשנת הייצור אינו מחיר שוק של משומש ואינו מחיר עסקה נוכחי. אין במוצר מחיר משומשות.
2. מאגר WLTP הישראלי אינו מכיל ל׳/100 ק״מ. נתון CO₂ נשאר נתון פליטות. אין המרה מומצאת לצריכת דלק ואין חיבור אוטומטי לנתוני EPA/קנדה.
3. מספר מושבים ודלתות נותן רשימה לבדיקה, לא הוכחה שכיסאות בטיחות מסוימים נכנסים. ISOFIX, תא מטען ומידות שימושיות אינם זמינים במקור שנבחר. המסנן “רק התאמה מתועדת” יחזיר כרגע אפס.
4. הקטלוג הישראלי המרכזי מתאר בעיקר פרטי משנת 1996 ומסחרי משנת 1998. יבוא אישי, אספנות ורכב חסר קוד דגם נשמרו במאגרים נפרדים ואינם מאוחדים אוטומטית לקטלוג.
5. האיורים הם איורים כלליים, לא תמונות אמיתיות של הדגמים.
6. רמת אבזור בטיחותי אינה ציון ריסוק. אין שימוש מסחרי בתמונות/טקסט Euro NCAP ללא הרשאה.

## הרצה מקומית

נדרשים Python 3.12 ומעלה. הקובץ `data/catalog.sqlite` כבר כלול בחבילת הפרויקט, כך שלא צריך למשוך שוב מאות מגה־בייט כדי להתחיל.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/gunicorn --no-control-socket --bind 0.0.0.0:8000 --workers 2 --threads 4 wsgi:app
```

פתחו `http://localhost:8000`. ב־Windows אפשר להריץ לצורכי פיתוח דרך Flask:

```powershell
py -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m flask --app wsgi run --port 8000
```

Flask development server אינו שרת הפרסום. לפרסום ב־Windows השתמשו ב־Docker או שרת Linux.

## אחסון חיצוני ודומיין

```bash
docker build -t car-clear .
docker run -d --restart unless-stopped -p 127.0.0.1:8000:8000 -e BASE_URL=https://YOUR-DOMAIN car-clear
```

החליפו YOUR-DOMAIN בדומיין שקניתם. הגדירו A/AAAA אצל רשם הדומיין לשרת והציבו Caddy/Nginx עם HTTPS לפני פורט 8000. אם משתמשים בשירות אחסון מנוהל: העלו את התיקייה, בחרו Docker, הגדירו `BASE_URL` לדומיין הסופי, `PORT` לפי השירות, `/health` כבדיקת זמינות ואת הדומיין לפי הוראות ספק האחסון. אין כאן דומיין או חשבון אחסון שנרכשו ואין פרסום חיצוני שבוצע.

דוגמת Caddy לשרת בבעלותכם:

```caddy
YOUR-DOMAIN {
    encode zstd gzip
    reverse_proxy 127.0.0.1:8000
}
```

בסיס הנתונים הוא צילום לקריאה בלבד. נדרש דיסק של לפחות 2 GB לבניית הפרויקט ורצוי 4 GB RAM בתהליך המשיכה והבנייה; שרת ההגשה אינו טוען את כל הרשומות לזיכרון. זו הערכת תכנון, לא תוצאת מבחן עומס. לאחר פריסה יש לבדוק זמני תגובה במארח שבחרתם.

## הנתונים והעדכון

`data/source-inventory.json` הוא מפת משאבי CKAN שנמצאו בחיפוש רכב; `data/download-manifest.json` מכיל כתובת מקור, רישיון כפי שפורסם, SHA-256 של הבתים המקוריים, שדות, מספר רשומות ותאריך משיכה. מאגרי הגלם המלאים שמורים בקבצי הנתונים בדרייב, בנפרד מחבילת ההרצה.

```bash
python3 scripts/pull_data.py --extended
python3 scripts/build_catalog.py
```

המשיכה חוזרת רק על קבצים חסרים. `--force` מושך מחדש את כולם, לכן לעדכון יומי יעיל צריך קודם לבדוק ETag/Last-Modified ולמשוך רק משאבים שהשתנו (הרחבה מתוכננת; אין כאן הבטחה שסנכרון אוטומטי כבר הופעל). בניית SQLite מתבצעת לקובץ זמני ורק בסיומה מוחלף הקובץ החי. אל תריצו שתי בניות בו־זמנית. גיבוי בסיס הנתונים הישן ובדיקת סטטיסטיקות נדרשים לפני החלפת צילום בפרסום.

קבצי המקור הממשלתיים אינם אחידים: חלקם מופרדים ב־`|` וחלקם ב־`,`; יש UTF-8 ו־Windows-1255. קודי תוצר ודגם עוברים נרמול מספרי, כדי שקוד 00928 יתחבר לקוד 928. כל שדה אחר נשמר במקור. במשאב הרישוי הגדול נשמרים הבתים המקוריים גם כאשר תצוגת הטקסט כוללת תווי החלפה; האזהרה מצוינת במניפסט. האתר משתמש בנתוני הדגמים והכמויות בלבד, לא ברשומות לוחיות.

## הוספת מידע מאומת

`data/verified-enrichment.json` מיועד לשיוך ידני לגרסה מדויקת. כל רשומה דורשת ID של גרסה, בודק, תאריך וכתובת מקור. אין התאמה לפי שם בלבד. דוגמת מבנה (אין להזין אותה כנתון אמיתי):

```json
{
  "id": "EXACT_CATALOGUE_ID",
  "reviewed_by": "שם הבודק",
  "reviewed_at": "YYYY-MM-DD",
  "consumption_l100": 6.2,
  "consumption_cycle": "WLTP",
  "consumption_url": "https://OFFICIAL-SOURCE",
  "child_fit": {"seats_tested": 2, "seat_models": ["..."], "configuration": "..."},
  "child_fit_url": "https://DOCUMENTED-INSTALLATION-TEST",
  "isofix_count": 2
}
```

חיבור צריכה מחייב אימות מנוע, הספק, תיבה, מרכב, שנתון ורמת גימור מול גרסה מקומית. בדיקת כיסאות מתייחסת לכיסאות והתצורה שנבדקו, לא לכל כיסא. נתון זר אינו נהפך לנתון ישראלי רק כי שם הדגם דומה.

## SEO ותוכן

כל דפי הגרסאות נגישים ונוצרים בשרת, אבל כרגע הם `noindex` עד עריכה ובדיקה. זה מכוון: לא מפרסמים 100 אלף עמודים דלים על בסיס העתקת מאגר. sitemap כולל כרגע דף בית, קטלוג בסיסי, מקורות ושלושה מדריכים. מסננים והשוואות נשארים מחוץ לאינדקס.

`data/editorial-pages.json` מאפשר להוסיף תוכן בדוק לפי מזהה גרסה עם `title`, `body`, `reviewed_by`, `reviewed_at`. לאחר הוספתו, העמוד יכול להיכנס ל־sitemap. השלב הבא הוא דפי משפחות דגמים שמאגדים שנתונים וגרסאות, עם הבדלים אמיתיים, נתוני שימוש ובדיקה. סכמת המקור אינה מזהה דור בצורה אמינה; אין איחוד אוטומטי שמעמיד פנים ששנתונים שייכים לאותו דור.

## בדיקות

```bash
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

בדיקות כוללות נרמול מפתחות, חיבור מקור ומחיר, חסרים ואפסים, תקציב, מושבים, הנעה, WLTP, קלט שגוי, ניסיונות SQL injection, מפרט, השוואה והנחיות אינדוקס. תוצאות בדיקות ותצוגה מופיעות ב־`docs/validation.md`.

## מבנה הפרויקט

- `app/` — שרת, תבניות HTML, CSS ו־JavaScript.
- `scripts/` — משיכה ובניית הקטלוג.
- `data/catalog.sqlite` — בסיס הנתונים להפעלה.
- `data/*manifest.json` — תיעוד המשיכות והמקורות.
- `docs/` — מיפוי מקורות, PRD ראשוני והמשך העבודה.
- `tests/` — בדיקות של הכללים והזרימות החשובות.
- `Dockerfile`, `compose.yaml` — פריסה עצמאית.

הקוד ניתן לשימוש ולשינוי בפרויקט שלכם. רישיונות הנתונים, התמונות והסימנים המסחריים נשארים של המקורות המקוריים; הורדה חינמית אינה רישיון שימוש זהה בכל המקורות.
