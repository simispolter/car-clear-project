# פריסה בענן

הפרויקט כולל `render.yaml` ל־Render ו־Dockerfile שנבדק בפועל. אין צורך להפעיל שרת במחשב המקומי.

הענף המיועד לפריסה הוא `codex/cloud-deploy` במאגר `simispolter/car-clear-project`. אין צורך למזג אותו ל־main כדי לפרוס.

## Render

1. התחברו ל־Render דרך GitHub ואשרו גישה למאגר אם הוא פרטי.
2. צרו Blueprint מהמאגר והענף `codex/cloud-deploy`, או Web Service מסוג Docker עם אותו ענף.
3. בחרו את תוכנית Free, בהתאם לזמינות ולתנאי השירות בחשבון. הקובץ מצהיר `plan: free`; אין תלות בדיסק מתמשך בתשלום.
4. בדקו שהשירות משתמש ב־Dockerfile בשורש המאגר וב־`/health` כבדיקת זמינות, ופרסו.
5. לאחר שהשירות פעיל, כתובת ה־HTTPS שהשירות נותן היא כתובת האתר שנפתחת במחשב ובנייד.

Render מספק את `PORT` ואת `RENDER_EXTERNAL_URL`. הקוד משתמש בכתובת הזו ל־canonical ול־sitemap; דומיין מותאם יכול להחליף אותה באמצעות `BASE_URL`.

חשבונות, הרשאות GitHub ויצירת שירות מחייבים התחברות של המשתמש. לא נפתח חשבון בשם המשתמש, לא נרכש אחסון, ולא נוצר עד כה אתר ציבורי.

## בסיס הנתונים

`data/catalog.sqlite.gz` הוא צילום דחוס בגודל כ־16.6 MB, המתאים לשמירה כקובץ רגיל בגיטהאב. בניית Docker משחזרת ממנו את בסיס הנתונים המקומי, מאמתת SHA-256, גודל, תקינות SQLite ומספר רשומות, ומסירה את הקובץ הדחוס משכבת היישום הסופית. אין צורך בהורדת נתונים ממשלתיים במהלך ההפעלה.

`python scripts/prepare_catalog.py` מאפשר אותו שחזור גם בפיתוח. בסיס נתונים קיים נשמר ואינו נדרס.

היישום קורא את SQLite בלבד. פריסה חוזרת מחזירה את צילום הנתונים שבקוד; בחירות להשוואה נשמרות בדפדפן ולא בדיסק השרת.

## אימות בסביבה הזו

- Docker נבנה בהצלחה לאחר שימוש בפרוקסי הרשת הקיים ובחבילת ה־CA הקיימת דרך mount זמני, ללא ביטול בדיקת TLS.
- בסיס הנתונים שוחזר ונבדק מתוך חבילה דחוסה בבנייה חדשה.
- ההרצה נבדקה כמשתמש UID 10001 על PORT=10000, כולל `/health`, דף הבית, חיפוש, עמוד מוצר ותמונה מקומית.
- הקישור הציבורי טרם נוצר או נבדק. אין להציג את שם השירות או דומיין משוער ככתובת פעילה.
- Cloudflare Quick Tunnel לא הצליח: בקשת HTTPS נחסמה בפרוקסי, והלקוח הרשמי ניסה DNS ישיר שאינו זמין בסביבה. זה אינו פתרון נתמך ללא שינוי יכולת הרשת.
- Render API והאתר אינם נגישים מהסביבה הנוכחית (403 בפרוקסי). דומייני Render נשמרו בטיוטת הגדרות הרשת להמשך בדיקה לאחר החלת ההגדרות.

במקרה של שינוי תנאי תוכנית Free יש לבדוק את האפשרויות המוצגות בחשבון, ולא לבחור תוכנית בתשלום באופן אוטומטי.

## Vercel

נוספו `index.py`, `vercel.json`, `.vercelignore` ו־`.python-version` לנקודת כניסה Flask ב־Vercel. קובץ SQLite המלא מוחרג מהעלאה; הצילום הדחוס נשמר בקוד. בזמן ריצה ב־Vercel, בסיס הנתונים משוחזר ל־`/tmp` בתיקייה המזוהה ב־SHA-256 של הצילום. נעילה בין תהליכים מונעת שחזור מקביל, ובקשות נוספות משתמשות באותו קובץ קריאה בלבד. מקור היישום נשאר לקריאה בלבד. כתובת השירות נלקחת מ־`VERCEL_URL` אם לא הוגדר `BASE_URL` מפורש.

מימוש Vercel הרשמי נבדק במאגר הציבורי `vercel/vercel`, בקבצים `packages/python/src/index.ts`, `entrypoint.ts` ו־`dependency-externalizer.ts`. קובץ ה־runtime מגדיר מסלול Flask ומגבלות לאריזה ולאחסון זמני. ההגדרה אינה מסתמכת על העלאת SQLite לא דחוס לתוך חבילת הפונקציה.

בדיקת תאימות מקומית: נקודת הכניסה פעלה בתוך קונטיינר עם מערכת קבצים לקריאה בלבד, 500 MiB של `/tmp`, הגבלת זיכרון 1 GiB ושני workers. בסיס הנתונים שוחזר פעם אחת; דף הבית, `/health`, חיפוש, עמוד רכב ותמונת הדגם הוחזרו תקין. זו בדיקת תנאי ריצה מקומית, לא פריסה אמיתית ב־Vercel.

טרם קיים חיבור לחשבון Vercel: לא נמצאו כלי מחובר, משתנה הרשאה או קובץ הרשאות CLI קיים. API Vercel הוחזר כ־403 בפרוקסי הרשת. דרישת `VERCEL_TOKEN` נשמרה בטיוטת הסביבה, עם יעד HTTPS מדויק `api.vercel.com`; יש להזין ערך דרך הגדרות הסביבה המאובטחות ולא בקוד. דומייני Vercel נשמרו להמשך חיבור ובדיקה. לאחר החלת ההגדרות צריך לבדוק את ההרשאה באמצעות API, לפרוס ולבדוק את הכתובת שהשירות מחזיר לפני שמצהירים שהאתר פורסם.
